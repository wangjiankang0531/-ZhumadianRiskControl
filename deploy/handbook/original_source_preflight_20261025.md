# 原项目共享资源的有时限启动预检

本工具解决共享失联时启动检查长时间等待且无法给出明确原因的问题。它不替代原项目后端，不改变账号、验证码或权限。

控制器先用一个自有Python子进程读取必需原平台包和显式原业务配置各最多64字节，默认总超时8秒。失联、空文件、读取中变化或不合规结果直接终止启动；子进程超时由subprocess.run取消并等待，不重试、不结束其它服务。返回标签和固定原因码，不输出路径、文件内容或异常信息。

预检放在原配置直接stat/完整哈希、全部前端扫描、实例/锁和原应用启动之前。--check-sources-only即使成功也直接退出，不生成候选实例。通过只证明当时文件头可读，后续原完整SHA、大小、数据所有权和进程边界验证全部保留；也不保证随后网络持续正常或所有其它共享读取均有时限。

最多8个显式绝对路径文件；标签必须唯一且格式固定。默认8秒，函数允许0.1至30秒；空/相对/控制字符路径、错误标签/布尔/结果、超范围期限拒绝。报告不包含源文件内容或路径，来源路径不在源码中固定。

验证：9项新回归包含真实小文件与缺失/空文件子进程、真实自有sleep子进程的超时取消等待，以及输入/输出错误。另有真实controller可读成功和缺失失败两项CLI验证，配合启动门和退出恢复共24项通过。真实控制器在2026-10-25共享失联情况下约8秒返回read-timeout；本方Python审计只放行一个精确探测子进程，没有修改文件/启动其它应用/创建候选实例。审计覆盖本Python链，不证明子进程或OS级隔离。原账号认证、正常完整启动与公网部署尚未验证。

恢复操作：先确认既有共享可读，再运行本轮已封存的交接启动器；核验ready、expiresAt、三入口及匿名接口后交用户手工登录。不要将旧ready文件、预检成功或HTTP静态页面代替真实后台/业务验收。网络变动应修复既有共享，不通过复制整目录资源或调整安全设置规避。
