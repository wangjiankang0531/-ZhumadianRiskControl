# 原前端与天津地图的完整内容清单和可迁移路径绑定

此前候选从旧实验网关收据读取四套前端与地图路径，并在启动器里覆盖首页目录。这不能直接作为独立服务器的显式输入。本阶段新增 original_frontend_roots：把内容身份和实际安装位置分离，完整核验 security_pc、emergency_pc、mobile、bigscreen、tiles 五个根目录，运行时由明确的私有路径绑定选择资源，不再需要旧网关收据。

## 数据范围和空间

当前实际候选的四套前端分别为 835/204/191/376 个文件，17789998/7199256/2815094/123221165 字节；天津原站地图目录为 11339 个文件、12108149 字节。五个根合计 12945 个文件、163133662 字节。这里的天津地图是原站二维瓦片目录，不是驻马店三维地景，也不代表原三维画面左右角清晰度问题已经验收。

本工具只写 2283903 字节私有内容清单与 715 字节路径绑定，不复制、提取或修改任何资源，不把地图复制到本机 D 盘。既有资源继续在当前目录/共享中被读取；实际服务器交付时可以直接传输到目标目录，再修改私有绑定，内容清单及其可信 SHA 不需重建。清单包含资源索引，不能加入 Git。

## 构建与选择

私有绑定对象固定为 schema=xnby.original-frontend.bindings.v1、appBasePath=/zhumadian 和恰好五个角色的 roots。路径可为显式绝对路径，或相对绑定文件目录的安全相对路径。根目录不得包含彼此，不允许缺角色；四套前端必须有 index.html，地图必须有文件。每个文件和目录都在清单中，额外空目录也拒绝，以保留静态路由行为。成员重解析点、非普通文件、源文件在扫描/排队后变化、大小和总数量超限均拒绝。

```text
python -B tools/original_frontend_roots.py prepare --bindings <私有路径绑定JSON> --output <全新私有内容清单JSON>
python -I -B tools/original_frontend_roots.py verify --manifest <内容清单JSON> --manifest-sha256 <构建侧可信SHA> --bindings <私有路径绑定JSON>
```

清单不写绝对准备路径，逐角色保留相对文件名、字节数/SHA、目录集合与内容树摘要。选择时完整重新核对全部字节和集合，不能仅凭 mtime 或旧缓存判断通过。修改安装位置只需换绑定；合成迁移测试在中文空格目录实际验证，清单 SHA 保持不变。

受控启动器增加 --frontend-roots-manifest、--frontend-roots-sha256、--frontend-roots-bindings，三项必须同时提供；完整选择发生在实例/持久锁/组件创建前，失败不回退。选中后原网关使用已验证五根目录，默认旧模式保留。当前 j16 仍是旧冻结启动器，新的路径选择尚未用于整套新候选启动。

## 共享读取性能与实际验证

初版逐文件 Path.lstat/open/stat 在共享小瓦片上实证较慢。原只读核验 PID 经归属核对后主动停止，实际终态为 1；没有完成清单，不称其自然成功，也没有停止候选或改动源文件。中止与 I/O 状态留档。改进复用目录枚举返回的元数据、在打开的文件句柄上核对前后状态，最多 8 个读取线程、每批最多 64 项，仍核验全部数据。

128 个真实共享文件分两组交错用两种方法各读一次，所有大小/SHA 一致。顺序两组共约 5.04 秒，有上限读取共约 1.00 秒，仅该样本约快 5.1 倍。最终真实清单生成 53.68 秒、完整选择 50.91 秒；不能把已中止旧全量过程当作完整对照成绩。

改进版完成全部 12945 文件的内容核验、真实选择分支和独立 Python -I 验证。随后逐个读取当前 j16 五个静态 HTTP 挂载，12945 个响应全部 200、163133662 字节逐 SHA 一致，HTTP 对照约 135.56 秒。用已验证根目录实际生成新网关配置，归一化本方日志/PID目录后与 j16 真实配置逐字节一致；两地图别名及业务/平台/管理 API 路由保持，无新 Nginx 启动。
