# 原大屏生命周期准备物与启动兼容（2026-10-25）

原大屏启动器此前将四个自有包装源码和编译类固定到早期原生 SQLite 校验目录。生命周期辅助类更新到最长十二小时后，这份旧校验仍要求旧哈希，因此下一次启动会在创建运行目录前拒绝。旧记录应当保留，不能通过覆盖其清单或省略哈希比较使启动通过。

新增 `prepare_original_bigscreen_lifecycle.py`，使用已有、固定哈希的 Java 8 与原大屏 Spring 依赖，独立编译当前生命周期类和自有 `BigscreenLifecycleFixture`。夹具只模拟实际 Spring 事件、文件停止请求及上下文关闭；不启动原应用，不运行 SQLite JNI，不打开数据库。它检查无效期限被拒绝、合法期限、ready 文件、正常关闭及关闭标记。事件构造器按实际 Spring API 选择三参数或四参数；本轮实际走四参数，三参数分支尚未在真实旧 SDK 下执行。

准备收据固定源码、Java 运行时、依赖、编译类和夹具日志的 SHA-256，并绑定此前十三项 SQLite 校验的准备物与终态收据。选择器拒绝半组选项、错误哈希、重复 JSON 键、非目标类路径、变化的源码/类/依赖、失败夹具和带原应用/数据库执行标记的记录。三个原包装类仍要求旧源码和旧编译字节一致；只允许明确选择的新生命周期类替换对应旧类校验。

调用准备器时指定现有工作目录与新的空输出目录：

```powershell
python -B tools/prepare_original_bigscreen_lifecycle.py --workspace <existing-workspace> --output <fresh-proof-directory>
```

后续原大屏候选使用新收据时，必须同时指定 `--lifecycle-receipt <proof-directory>/receipt.json` 与 `--lifecycle-sha256 <printed-sha256>`。不提供时保留原旧校验规则；不会自动放宽、自动重新编译证明或静默采用当前文件。选择校验在创建候选网关目录或启动程序前完成。准备物变更后需要新的证明及明确哈希，不修改旧收据。

真实启动器的 `compile_wrappers` 同时用于无业务启动的编译预检和正式受限启动，避免只测试另写的一份近似编译逻辑。运行时编译集合必须恰好使用经验证的生命周期类；其他三个包装类逐字节保持旧值。

本轮验证：

- 五项 Python 校验回归以及既有进程等待/平台就绪回归，共二十项通过；Java 8 实际生命周期夹具五项通过。
- 调用真实启动器编译函数生成四个包装类，其中三个旧类字节不变，生命周期类与刚执行的夹具产物一致。
- 一次独立、最长两分钟、无重试的原大屏后台运行通过。只用自有 12 KiB SQLite 副本，原程序 ready、原表四条记录、未映射 HTTP 请求返回 404，随后正常关闭且退出码为零，无强制结束。
- 进程内原约束仍在；固定 SQLite JNI 加载一次。记录了八次非许可原生库、三次非回环 DNS、一次未许可回环连接的拒绝，不能称为零拒绝，也不能将 Java 进程约束描述为完整 OS 沙箱。
- 原数据库与原运行包 SHA 保持；未请求视频设备，未重启既有业务或三维服务，未发布公网。
