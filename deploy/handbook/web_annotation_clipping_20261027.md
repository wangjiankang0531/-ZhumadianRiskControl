# Web annotation clipping (2026-10-27)

The viewer previously projected every original vertex and skipped the entire line or region if even one vertex lay behind the near plane or beyond the far plane. A visible interior sample could be in the viewport while both painting and picking discarded the feature. The baseline reproduced this using the exact former project() and hit-target functions.

annotation_clipping.js clips segments and polygon fill in homogeneous coordinates against the six view planes before perspective division. Original stroke edges are kept separate from the clipped fill contour, so viewport/near boundaries do not become invented outlines or hit edges. Disconnected visible polyline intervals remain separate. Stroke padding accounts for width/hit tolerance. Region fill and picking use consistent even-odd coverage, including clipped concave lobes. Selection uses the same original clipped strokes. The optional geometry argument preserves existing hit-target callers. Saved DLG, coordinates, feature IDs, style values, groups and data schema are unchanged.

Fifteen new clipping checks and all 735 Web tests passed; related focused tests total 41. The actual viewer was compared in Chrome using the exact before-source bundle and new bundle, one synthetic three-feature document, read-only existing landscape, and matching 1600x900 page / 1600x753 scene dimensions. Before: crossing line and region were absent and unselectable. After: both were visible and canvas clicks selected qa-line / qa-region. Point selection and layer hide/show passed in both; console errors were zero. Initial screenshots had different viewport heights and are retained separately, excluded from the matched comparison. Direct canvas readback is not exposed by the browser bridge; image inspection and actual picking were used. Status bars near 1FPS do not prove performance improvement.
