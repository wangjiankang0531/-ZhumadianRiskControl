# 原后台标准 JAR 封包与核验

原 Spring Boot 归档在本次 Java 17 进程约束下，可能因 JDK 对虚拟嵌套 JAR 的检查而出现类定义失败。`tools/reference_flat_runtime.py` 将原 `BOOT-INF/classes` 的全部业务类与资源组织为标准 JAR，通过清单引用原依赖文件，保留原业务实现与资源字节。

工具不启动 Java、不下载依赖、不访问数据库。生成物属于私有运行制品，不能随工具源码上传 Git。

## 输入与输出

输入为既有原源码重建归档、与归档内 `BOOT-INF/lib` 逐字节一致的依赖目录，以及原归档的固定 SHA-256。输出目录必须尚不存在。

输出包括：

- `application.jar`：原业务类、原资源和标准清单。`Main-Class` 取原 `Start-Class`。
- `receipt.json`：原归档、输出制品、每份业务文件和依赖文件的 SHA-256、大小及相对路径。

所有依赖按原归档顺序写入清单 `Class-Path`，不复制依赖。清单 URI 对空格等字符编码，物理行包含 CRLF 不超过 72 字节。保留原文件相对顺序，并显式生成 Java 包与资源目录条目，支持 Spring 按包发现组件及按路径发现资源。

移动制品时必须保持清单中依赖的相对位置。复制一个 `application.jar` 到任意目录不构成完整部署。

## 构建期操作

以下路径是示例，使用时替换为已核验的实际输入：

```powershell
python -B -X utf8 tools/reference_flat_runtime.py build --source work/source/app-source.jar --dependencies work/source/libs --output work/flat-runtime --source-sha256 <固定原归档SHA256>
python -B -X utf8 tools/reference_flat_runtime.py verify --output work/flat-runtime
```

`build` 在写输出前检查原归档 SHA、布局、所有依赖字节和路径。拒绝目录穿越、重复归档成员、依赖名冲突、应用资源覆盖清单、缺少原入口类及输出目录复用；应用文件总大小上限为 128 MiB，超过时明确失败，不截断。

`verify` 重新读取原归档、输出 JAR 和原依赖，核对实际字节、目录条目、成员顺序及清单。当前验证面向构建环境，需要原输入可用；服务器部署仍须对获准制品与依赖清单单独核验。

## 已完成验证

```powershell
python -B -X utf8 -m unittest discover -s tools -p test_reference_flat_runtime.py -v
```

14 项测试覆盖原文件保留、依赖损坏前后检测、输出损坏、错误来源 SHA、输出复用、路径穿越、清单覆盖和注入、长清单/空格 URI、确定性构建及包目录发现要求。

本轮私有实际运行记录确认：

- 768 个原编译类、97 份原资源、220 个原依赖全部逐字节一致，依赖复制数量为 0。
- 新标准 JAR 为 1,372,539 字节。原组件代码和原配置文件内容未修改。
- 在本次 Java 17 进程约束下，全部 768 个原类定义成功；类来源均为新 JAR，原业务类初始化日志为 0。此步骤只定义类，没有调用原入口或业务服务。
- 另行实际启动原入口，加载 736 个业务类；本轮相同测试配置下，854 条 Bean 注册元数据与原编译目录启动基线逐行相同，包含 191 条直接标为原业务类的定义。比较字段为名称、类型、工厂 Bean、工厂方法和延迟初始化标志。
- 实际注解调度观察为移除 1 个处理器、剩余 0 个。当前启动在 Redis 依赖处失败，未完成应用上下文就绪或数据库业务验收。

类定义成功不能单独证明 Spring 组件完整。首版封包遗漏显式目录条目时，类定义可成功，但组件发现不足；该问题已由包目录条目、目录发现检查及实际 Bean 定义对照覆盖。

## 阶段边界与运维要求

本工具只解决封包和原文件保留问题。本轮 Java 进程约束、假令牌、回环测试 URL 与关闭调度设置均为独立实验接线，不是原业务配置或正式运行默认值。未关闭 JDK 的 JAR 检查，未修改系统策略。

原测试数据库完整恢复、字段类型往返、原 Java/JNPF 真实接口、电脑及手机内部操作、认证、写入、审批与公网同版部署尚未通过。Redis 连接失败不能据此推断原 Redis 服务故障，也不能将此封包验证写成严格复刻阶段完成。

当前没有数据库字段、索引、状态或归属变更，不产生替代原库的数据库模型。保留原归档和必要回滚制品；测试后仅清理已核验可重建的自有临时文件。
