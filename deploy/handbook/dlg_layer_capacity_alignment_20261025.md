# EXE与Web的1000图层容量统一（源码候选）

2026-10-25。本轮修复实际文档兼容缺陷，尚未生成或替换编辑器运行包，也未部署250、252或公网。天津完整复刻、20秒外围清晰度及UE长期指标仍未验收。

## 问题、行为及实现

Web与Python三维发布校验器允许1000层，而native/landscape_document.hpp原先只允许256层。相同合法文件超过256层后，网页可以接受，但EXE文档层拒绝读取/保存。另一个问题是编辑器“新图层”按钮没有在修改文档和撤销检查点之前阻止超限。

原生文档层现用kMaximumLayerCount=1000统一导入/保存上限；requireLayerSlot在新增前检查容量。native/landscape_editor.inl的新图层分支先调用它，再建立撤销检查点和追加图层。第1000层允许新增，第1001层提前报错，不因本次失败改变图层文档。Web/Python既有1000层上限不变；每文档10000要素、每要素1000顶点和16MiB文件读取限额仍保留。本轮不改DLG结构、坐标系、样式或数据库模型。

合成文件包含自定义PNG点图标、独立透明度、虚线宽度、凹区域、文字标牌、隐藏/锁定层及首尾层标注。JSON完整结构相等证明本轮样式数据往返，不能据此宣称GPU视觉、千层交互性能或完整编辑器操作验收。

## 构建与复现

使用已有x64 MSVC开发者环境，以及已有GLM、nlohmann头文件；无需安装依赖。在Application目录中，将下列占位路径替换为既有头文件根目录和新建的专用合成测试输出目录：

```powershell
cl /nologo /std:c++20 /EHsc /utf-8 /MT /O1 /W4 /I native /I <既有GLM和JSON的include目录> tools/test_landscape_document_capacity.cpp /Fe:<专用测试目录>/document_capacity_test.exe /Fo:<专用测试目录>/test.obj
& '<专用测试目录>/document_capacity_test.exe' '<已创建的绝对合成输出目录>'
```

两个输出目录均须独立于用户DLG和运行包，测试会在合成输出目录写入固定测试文件名。完整本轮编译命令、编译器/源码/测试二进制SHA和终态退出码在Document/Deployment/dlg_layer_capacity_20261025的baseline、candidate、final/receipt.json中。独立程序不链接整个引擎。测试源码经已有clang-format处理；旧配置的两个较新选项由工具支持的unknown警告保留，配置未改。初次格式化失败、首次行尾调整被自动审批拒绝的原因及随后整文件SHA/差异核验记录保留；最后只转换核实过的当前字节行尾，没有从Git覆盖当前工作文件。

这是源码候选。当前250/252用户已能使用的运行包仍有各自冻结清单，不直接覆盖头文件、EXE或脚本；本轮没有重启用户服务、改业务库或用户图层。后续需要在保持14项原生held修改隔离的条件下构建明确版本，再做实际编辑器导入/新增/保存/重开、Web发布和目标机测试。旧EXE的256层限制在正式新包验收替换前仍存在，不应把大于256层的候选兼容证明当作当前运行包已支持。
