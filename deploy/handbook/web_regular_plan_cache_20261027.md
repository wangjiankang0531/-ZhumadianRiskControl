# 可见根事务连续加载与普通计划缓存（2026-10-27）

本轮属于实际进展：解决只读覆盖加载中已选根反复被其它未测量估值挤走的问题，并将有界元数据缓存接入普通路径。20秒全视口清晰、全部区块可用及最终项目目标仍未通过。

## 设计与实现

普通源页路径接入已有SourcePlanCache，上限4 MiB/256条，仅缓存已校验且不可变的元数据，不缓存可用性或租约。实际载荷仍复核marker SHA、源身份和独立租约；版本变化仍失效重取。QA可用planCache=0关闭普通分支缓存，索引分支既有行为不变。

发现只读预览计划端点拒绝前端固定wait_ms=200提示，触发422后再取一次。现仅根/族的metadata-plan端点接受这一精确提示；其它值、重复参数、额外convert参数、实际载荷带此查询仍拒绝。现有准备资源直接返回，不引入转换或原生进程。新增真实HTTP回归覆盖无租约准入/磁盘不变及非法请求。

单接缓存仍约799次候选尝试，调度空闲累计27秒。当前preparedCoverageFirst已按可见根覆盖排序，但allocationStillBest只有索引分支保持活动事务；普通只读分支测得真实收益后，被其它未知收益的上界抢占，又在每次cut更新后重复测量，造成反复排队。本轮仅让此覆盖策略下仍活动的根保持本事务；实际stillWanted、正收益、全额预算、版本/租约、完整页及取消/恢复校验全部保留。普通族收益竞争不改变。QA用rootCommit=0回退该根保持行为。
