# 天津业务源码与原部署包的分层指纹核对

本阶段只读比较参考源码随附包、已存在的同源重编包、从原部署包制备的既有平铺运行包。没有重新编译原业务应用、加载执行原业务类、连接数据库或切换公网。不得以原包名称一致代替源码与运行逻辑一致的验证。

## 实现与复现

运行 tools/audit_original_business_class_fingerprints.py --workspace <既有天津工作目录> --output <该目录下不存在的新输出目录>。需要此前固定 SHA 的三份归档、重编收据、原运行依赖收据、863 项源码输入清单及既有 Java 17 和 Spring ASM；没有下载依赖。Java 辅助工具逐项只读读取 768 个业务 class，单 class 上限 4 MiB，规范化字节只在内存中生成，不保存或执行。参数元数据单独记录，避免 ASM SKIP_DEBUG 移除 MethodParameters 后被误认为完全一致。

分别记录原字节、排除 debug/frame/MethodParameters 的规范化结果、独立类元数据/字段集合/方法集合、成员顺序无关聚合和反射参数元数据。八个自有合成类变体验证 debug、参数开关、参数名、方法声明顺序、代码增量、运行注解与字段常量的区分。这些是差异定位指纹，不能证明完整行为等价。

## 实际结果与边界

- 863 项既有重编输入（766 Java、97 资源）与当前 Reference 及工作副本全部 SHA 一致；三包各 768 class，输入归档 SHA/大小/mtime 前后保持。
- 参考随附包与既有重编包原字节 723 相同、45 不同；规范化后仍 45 不同，类元数据和字段集合全部一致。选查 BaseFile.toString、部门角色查询、告警结果、隐患状态、PDF 和 HTTP 方法时，差异集中于对象字符串拼接前增加 String.valueOf 及相应跳转偏移。仅此六处已查看，不将其扩展为全部 45 类行为等价，也未执行真实业务验证。
- 参考随附包与原部署包原字节 58 相同、710 不同；规范化及成员顺序分离后 759 相同、9 不同，反射参数元数据另有 710 不同。类元数据全部相同，字段集合有 4 类不同，方法集合有 9 类不同。不能把 710 项全部归为参数差异。
- 原部署包的 OtherWorkFileDock.files 为字符串，参考源码随附包为 List；原附件发送方法也存在 JSON 序列化/日志写入差异。第三方单位名称字段、人员 userName/username、资质与事故更新方法也存在具体差异。记录保留，不为消除差异擅改原站或当前运行包。严格复刻须用原站实际行为确定验收依据，并记录源码/部署版本冲突。
