# BC7独立通道编码与逐级画质准入（2026-10-27）

本阶段继续处理中远景512MiB跟踪预算下的纹理质量问题。现用近景预览仍为http://127.0.0.1:65357/ ，29根约508MiB；新源码未替换现用包，当前压缩索引仍为空，公网及252不改。完整中远景、全园区、冷盘20秒清晰度仍未通过。

纯JavaScript增加显式mode0-1-2-3-4-5-6配置，在面积≤16384的小mip搜索Mode4/5独立通道编码：Mode4有4种通道旋转和2种索引分配，Mode5有4种旋转，原不透明alpha保持255。边缘不足4x4时仅按真实可见像素评价候选，严格不增加误差；编码前后源JPEG SHA/mtime保持，不调用原生编码器。CLI静态导入的6个编码模块均记SHA；旧已封存清单不回写。

参考[Microsoft模式参数](https://learn.microsoft.com/en-us/windows/win32/direct3d11/bc7-format-mode-reference)和[Khronos BPTC格式](https://raw.githubusercontent.com/KhronosGroup/DataFormat/main/bptc.txt)，不是从held原生代码移植。独立参考与Pillow核对12种模式/旋转/索引配置各4个样本，共48布局样本逐字节一致；完整块二维颜色样本实际选择新模式并降低误差，5种非完整边缘尺寸均保持真实像素误差不回退和确定性。

本轮发现并实际修复准入缺口：原ReadOnlyTextureStore只核验格式、完整mip和SHA，会接受accepted=false的真实141清单。新增Python/浏览器公共数值契约，必须整链与每一级accepted严格为true，声明门槛不能低于40dB或高于P99=16/最大值96，数值须有限且逐级实测达到门槛。缺失证明、布尔冒充数值、NaN/Infinity、弱化门槛或任一级失败均拒绝。服务返回脱敏质量证明，不返回producer、原图引用、源RGBA SHA或执行耗时；已钉住的文件/载荷SHA要求保持。旧只有格式/哈希而没有画质证明的索引现在启动失败，必须离线重验，不自动补accepted，不放宽兼容。
